# 設計文件

## 想重現的感覺

目標不是復刻某一款遊戲，而是重現九〇年代末那類便利商店經營遊戲帶給人的感覺。拆開來是這幾件事：

| 當年的感覺 | 這個遊戲的做法 |
|---|---|
| 從選址開始，每個商圈的客人不一樣 | 3 個城市 × 4 個店面，客層比例、人潮、店租、週末倍率、對手都不同 |
| 進貨、訂價都自己來 | 22 種商品各自設定「補到幾個」與售價（原價的 70%～150%） |
| 規劃貨架 | 8 種設備、最多 12 個位置；沒有那種設備就不能賣那類商品 |
| 招募店員、排班 | 早班、晚班、大夜三班；沒人顧的班不營業 |
| 打廣告、跟對手搶客人 | 吸客力決定商圈市佔率；長期壓制可以讓對手收攤 |
| 看著 Q 版小人在店裡走來走去 | 店面裡的客人會逛貨架、排隊、冒對話泡泡 |
| 「叮咚」一聲和輕快的音樂 | 即時合成的門鈴、收銀機音效與原創背景音樂 |
| 突發狀況 | 17 種事件，多數要你做選擇，結果有好有壞 |

## 核心循環

```
        ┌──────── 看結算與咚咚的建議 ◄───────┐
        ▼                                    │
  調整進貨／售價／設備／排班／廣告            │
        │                                    │
        ▼                                    │
  開門營業（24 小時，每小時結算一次）──► 日結 ─┘
```

目標分兩段：

1. **30 天評比**：依總資產（現金＋庫存＋設備半價）頒銅、銀、金牌。
2. **現金 300 萬**：存到之後可以光榮退休（破關，天數與累計營收記進名人堂），或頂下一間分店繼續經營。用模擬玩家量過，單店大約要 130～330 天，看店面難度。

## 模擬規則（`src/engine.js`）

- **時間**：一天從 06:00 到隔天 06:00，共 24 個小時刻；`tickHour` 推進一小時。
- **來客數**：商圈人潮 × 市佔率 × 該小時各客層的分布 × 天氣、週末、活動加成，取卜瓦松亂數。
- **市佔率**：自己的吸客力 ÷（自己＋所有對手＋固定的「路過沒進來」）。吸客力來自口碑、販售品項數、廣告、售價高低、升級設備。
- **每位客人**：抽一個客層 → 想買 1～4 樣（依客層喜好 × 時段 × 天氣加權）→ 逐樣檢查：有沒有賣、有沒有貨、嫌不嫌貴 → 結帳能力不夠就排隊走掉。
- **滿意度**：買到幾樣、缺貨幾樣、嫌貴幾樣、店員親切度、整潔度一起算分，口碑往當小時的滿意度靠攏。
- **結帳能力**：當班人員的「手腳」加總（第二收銀台 ×1.35）。超過的客人會把東西放回去走掉。
- **日結**：鮮食與報紙報廢 → 扣薪資、店租、水電 → 依進貨目標自動補貨（隔天清晨到）→ 對手成長 → 抽明天的天氣。
- **透支**：現金低於 −$100,000 就倒閉。
- 所有亂數都來自存在狀態裡的種子，所以同一個種子會重現同樣的結果，存檔再讀檔也不會改變後續發展。

## 連鎖經營（`src/chain.js`，v0.3 起）

- 現金第一次達到 300 萬的那天日結，會問要退休還是開分店；之後隨時可以從「總部」決定。
- 頂讓金：高雄 100 萬、台中 120 萬、台北 150 萬，含基本設備與第一批貨。最多四家店。
- **共用錢包**：所有店看到的是同一筆現金。做法是每家店仍然各有一份完整的 `engine.js` 狀態，每次有店動到現金就把數字同步給其他店，所以單店規則一行都不用改。
- **時間同步**：每小時先推進你正在看的那家店；它遇到事件就整個連鎖停下來等你。其他分店遇到事件，由當班的人照第一個選項處理，再用跑馬燈回報。
- 分店沒有店長（你）站櫃台，三個班都要請人；分店不參加 30 天評比。
- 已知的簡化：同一個城市的兩家店，天氣是各自擲骰的，可能一家颱風一家晴天。

## 進貨的時間

- 「補到」是每天自動補貨的目標量。打烊結算時下單，**隔天清晨 06:00 到貨**；鮮食與報紙當天報廢，所以是整批重補。
- 「立刻到貨」是緊急補貨：馬上上架，多收三成運費。
- 進貨分頁最上面是下一班貨車的倒數，以及照目前設定會補幾種、幾件、多少錢；每項商品也各自標出明早會補多少。
- 商品可以用搜尋（比對名稱、設備名稱與同義詞，只打其中幾個字也可以）或分類（賣完了、沒補滿、各種設備）篩選。

## 音樂

三首原創小調子，一個班一首：早班明亮輕快、晚班放鬆、大夜又慢又安靜。換班時先響一聲提示音再換曲，顧問也會報出這一班是誰上工。

## 介面

- 手機直式為主：上方是招牌般的資訊列，中間是店面，下方是今日時間軸、顧問咚咚的話、速度鍵與五個分頁。
- 開著分頁或視窗時時間暫停，可以慢慢想。
- 今日時間軸：24 根長條是每小時來客（橘色＝已發生、藍色＝預估、斜紋＝沒人顧店），下面是三個班的人手。
- 視覺語言見下一節。

## 視覺設計（v0.2 起）

玩法是當年的，畫面是現在的便利商店：冷白的店內燈光、乾淨的白色檯面、淺木紋、整面落地玻璃。

| 項目 | 設定 |
|---|---|
| 顏色 | 地磚灰 `#EEF2F5`、純白 `#FFFFFF`、墨色 `#16202A`、招牌橘 `#FF6A13`、招牌綠 `#00A58E`、價格牌黃 `#FFD52E`、夜空 `#070F1C` |
| 字型 | 粉圓（Huninn）一套到底；層級靠字級與顏色，不靠粗細 |
| 店面 | canvas 向量繪圖，邏輯座標 192×160，實際解析度跟著螢幕密度走 |

整個介面只有三個主題，其餘一律安靜：

1. **招牌色帶**：橘色長帶，右端斜切接一段綠色。出現在每個視窗、分頁與資訊列的頂端，也是店內招牌、櫃台與設備上的品牌線。刻意不用上下疊放的橫條，避免和現有連鎖品牌的識別相似。
2. **價格牌**：所有「錢」都長得像貨架上的黃色價格牌——現金、售價。
3. **收銀明細**：每日結算是一張下緣有鋸齒的明細，右上角蓋一個「賺」或「賠」的店章。

店面裡的現代便利商店元素：玻璃門冷藏櫃、開放式鮮食櫃、保溫蒸箱與關東煮鍋、臥式冰櫃、咖啡吧、冰沙機、觸控收銀機與感應刷卡機、自動玻璃門與防撞圓點、排隊地貼、資源回收桶、雨天的傘架；升級後會出現多功能事務機、監視器、冷氣、窗邊座位區。

## 刻意不做的事

- 不用真實品牌的名稱、商標或招牌配色排列，不用原作的名稱與素材。
- 不做內購、廣告、連線；存檔只放在瀏覽器裡。
- 不追求寫實的會計：進貨時付現、賣出時認列成本，夠玩家判斷賺賠就好。
