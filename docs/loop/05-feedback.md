## 深入與定案

**進貨。** 規則其實一直是「打烊下單、隔天清晨到」，問題是畫面上只有一句小字。沒有改規則，改的是說清楚：最上面放下一班貨車的倒數與這一車會補多少；每項商品標出「明早 06:00 到貨 +N」；緊急補貨的按鈕改叫「立刻到貨」並寫出數量。搜尋與分類是就地顯示／隱藏，不重畫，所以打字時輸入框不會跳掉。

**三百萬。** 「賺滿三百萬」定義成「現金達到 $3,000,000」，因為開分店要花的就是現金，玩家最好理解。定之前先用模擬玩家量過要多久：

| 店面 | 現金到 300 萬的天數（3 個種子） |
|---|---|
| 高雄 新堀江商圈 | 126、139、149 |
| 高雄 西子灣碼頭 | 136、140、154 |
| 台中 一中街 | 213、226、227 |
| 台中 大里住宅區 | 129、146、152 |
| 台北 西門町 | 245、248、266 |
| 台北 公館學區 | 319、360、400 天內沒到 |
| 台北 永和巷弄 | 300、314、328 |

×1 一天 36 秒、×3 一天 12 秒，所以最快的店面大約是半小時到一個半小時的純營業時間，再加上調整的時間。這是長期目標，數字放在 `chain.js` 最上面，要調很容易。

**連鎖怎麼接上單店引擎。** 引擎裡每家店都有自己的 `cash`。沒有去改引擎，而是在外面包一層：每次有店動到現金，就把數字抄給其他店。好處是單店的規則測試與平衡完全不受影響（只有一家店時，連鎖的結果和單店逐位元相同，有測試）。

**速度。** 拿掉 ×8，剩下暫停、×1、×3。舊存檔如果停在 ×8 會回到 ×1。

## 批判

| # | 問題 | 處理 |
|---|---|---|
| 1 | 切換店面後結果不同？測試第一次是紅的 | 查了：營收、淨利、來客都一樣，不同的只有歷史紀錄裡的「當時總資產」（結算順序不同，抄到的現金差一個小時）。是測試比錯欄位，不是規則有問題 |
| 2 | 分店開幕時，「店長」這個不用薪水的人不可能同時站兩家店 | 分店沒有店長，開幕時自動請一位早班；店員頁改成提醒三個班都要請人 |
| 3 | 分店到了自己的第 30 天會拿獎牌，而且總資產算的是整個錢包 | 分店不參加 30 天評比 |
| 4 | 一個 commit 做了好幾件事，更新紀錄只會出現一條 | 版號腳本改成內文裡每一行 `feat:`／`fix:` 都各自成為一條 |

## 這一圈沒有驗證到的

- **音樂沒有用耳朵聽過。** 開發環境不能播放聲音，只確認了換班時會切到對應的曲子。三首曲子好不好聽、音量平不平衡，要實際聽。
- **300 萬的天數是模擬玩家跑的**，真人會比較快還是比較慢不知道。
- **多家店同時跑的流暢度**沒有在手機上測過。
- 同一個城市的分店，天氣是各自擲骰的。
